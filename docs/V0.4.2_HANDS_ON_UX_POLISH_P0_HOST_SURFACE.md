## 4. Native Undo for expression trial switching — supported, with an ownership constraint

The host exposes public `UndoRedoManager.Record()` behavior used by the current product placement core.

A native behavior probe attached one real `Timeline` to an `UndoRedoManager`, then performed:

```text
Record()       // open one logical history record
trial A        // Timeline Items = A
trial B        // Timeline Items = B
Record()       // close record
```

Observed result:

```text
after close: IsUndoable = true, Timeline = final trial B
Undo once:   Timeline = initial state
Redo once:   Timeline = final trial B
```

Marker:

```text
UNDO_TRIAL_SESSION_RESULT=ONE_RECORD_INITIAL_TO_FINAL
```

This proves the user's desired history semantics are possible **without a custom Undo stack**: intermediate candidates inside one native Record session need not become separate Undo entries.

### Critical ownership constraint

This result is not permission to leave a native Record session open indefinitely while arbitrary YMM4 editing continues. Any unrelated native mutation recorded while the session is open could become part of the same history entry.

H3/H4 must therefore model an explicit root-coordinator `ExpressionTrialSession` (name may vary) with a finite lifecycle:

1. session begins immediately before the first Plugin-owned trial mutation for one Voice;
2. only Plugin-owned expression replace/remove mutations are admitted while it owns the session;
3. candidate changes for that same row may reuse the session;
4. session **must close before** row change, task/tab change, Tool hide/close, refresh/reload, settings operation, external Timeline mutation, native Undo/Redo, or any other operation that could create unrelated history;
5. stale/external mutation ends the trial session before any new replacement attempt;
6. once closed, one native Undo must restore the pre-trial expression state and one Redo must restore only the final chosen expression.

Do not clear unrelated Undo history. Do not use the internal `UndoRedoCommandCollector` from product code; although reflection exposes its surface, direct product compilation proved it is not a supported accessible type. Do not use private reflection to reach it.

Product Native acceptance must explicitly prove both:

- several Plugin trial candidates for one Voice produce **one** native Undo step initial -> final;
- an unrelated Timeline operation cannot be captured into that trial history entry.

## 6. Boundaries

P0 does not prove:

- final drag ergonomics or tile colors;
- the full immediate expression replacement implementation;
- real PSD rendering fidelity;
- that a long-lived open Record session is safe (it is explicitly disallowed by this workplan);
- final Tool ordering inside Utilities;
- final human comprehension of Item-first Settings.

Those belong to H1-H6 product Native acceptance and the later real-user hands-on gate.
