## Release gates

Version 0.4.2 / assembly 0.4.2.0 must agree across project, loaded native assembly, release DLL, package name and current usage documentation.

The retained P1-P9 / W3-W12 / WUX1-WUX13 ladder runs alongside R1-R14. Required manifests are core acceptance (18 requirements), retained Task UX (12), workflow acceptance (10), and relative acceptance (19). The retained Task UX manifest keeps its 0.4.0 specification version; the current core/workflow/relative manifests identify this 0.4.2 build.

`ValidateRelativeEvidence.ps1` independently requires exact native stage markers and exact relative manifest identity, host, check IDs and stage coverage. The packager runs one valid and ten deliberately damaged evidence inputs. A producer's standalone PASS field is not enough. RunNative removes the previous relative manifest before starting so a stale file is not reused.

Release and isolated proof builds must each have zero compiler warnings/errors. The exact distribution DLL must load in native YMM4 without proof code. The archived DLL hash must match that smoked DLL. `.ymme` must contain only its allowlisted payload beneath `Ymm4TemplatePlacer/`, including `v042-acceptance.json`. Source ZIP must contain the relative design, roadmap, current/legacy usage, implementation and proof sources.

`provenance.json` records source HEAD, checkout commit/tree, native run/attempt, host hash, assertion count, manifest counts and distribution DLL hash. `package-checks.json`, `SHA256.json`, `evidence-guard-tests.json`, build logs, screenshots and proof logs are the evidence. A PR merge checkout can differ in commit SHA from the source branch; use its recorded tree to compare exact code.

## Migration and operational boundary

Old Library, Character/Style Palettes and Expression/Selection Presets stay readable and unchanged on load. No ambiguous absolute-to-relative migration is invented. The explicit compatibility workspace retains old behavior. New Character palettes are bootstrapped from eligible live Face Templates in memory and become persistent through an explicit settings operation.

Normal tiles are add-only, unassociated placement; associated expression placement and Resync are the bulk Voice-list path. Multiple memberships of the same source are deduplicated in expression candidate order; normal tiles retain per-set placement choices. Multi-item intrinsic durations are preserved rather than silently stretched.

The new settings workspace uses up/down ordering; the old workspace's drag handle is not claimed as a new-settings drag feature. Save new settings drafts before closing the Tool; new draft resume across host ViewModel replacement is not covered by the retained legacy resume contract.

CharacterName is the logical grouping key. Real duplicate registered Character definitions stop placement. `IntentCharacterRegistry` uses an isolated, fixed read-only compatibility adapter because the host registry type is internal. This is not a claim of compatibility with future YMM4 versions.
