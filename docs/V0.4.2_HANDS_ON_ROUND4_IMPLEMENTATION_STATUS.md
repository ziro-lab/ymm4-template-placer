## R4-C first small checkpoint: transaction prerequisite (CT)

Scope: immutable session-opening snapshot, detached commit/rollback candidates,
latest-successful-commit fingerprint, and the existing protected settings store.
The root remains responsible for the working draft, publication and UI lifetime.

The new `SettingsEditTransaction` performs no implicit load/reload/retry and never
advances its fingerprint after a failed write. Both commit and rollback use the
existing validation, atomic replacement, disk digest and cross-instance lock.
The operation returns a detached result for the root to publish after success.

`NativeHandsOnRound4SettingsTransactionProof` exercises twenty CT checks against
the real settings store inside the existing Windows/YMM4 lane. The independent
Round 4 checkpoint validator additionally requires CT evidence and applies its
existing invalid-evidence fixtures to it. A/B and all earlier gates remain required.

Marker for this prerequisite only: `HANDS_ON_ROUND4_CT=PASS`.
It is deliberately NOT `HANDS_ON_ROUND4_C=PASS` or `HANDS_ON_ROUND4=PASS`.
Until a run for the new commit succeeds, this checkpoint is implemented but unverified.
