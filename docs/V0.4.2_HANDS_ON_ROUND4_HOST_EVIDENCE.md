## 2. Real-user hands-on findings after Round 3

The user’s actual editing pass established the following product observations.

### H1 — Preview expression update is usable

Applying an expression in the batch screen and navigating to the Voice showed the expression/video change in Preview.

Product consequence:

- preserve the existing public Preview seek/navigation route;
- unify dropdown-open with row navigation instead of adding another Preview mechanism.

### H2 — placement surface loses useful vertical space

The full-width Generic layer editor consumes too much vertical space.

Desired compact semantic layout:

```text
汎用・時間位置                  レイヤー
再生位置にテンプレート
```

Product consequence:

- move Generic layer control into the header;
- remove permanent Set-wide chrome;
- use bottom-right Settings for current-Set configuration.

### H3 — Set-wide left-click menu is unstable

Current Round 3 `Set全体` left-click can open and immediately close; right-click can reach it.

Product consequence:

- the obsolete top Set-wide menu is removed in Round 4;
- any new primary popup must have deterministic left-click open semantics.

### H4 — Voice row height is too rigid

Column width can already be adjusted, but long Serif text is ellipsized in a fixed 36px row.

The user explicitly rejected shrinking text or forcing each row to full automatic height.

Product consequence:

- one bounded common row-height setting;
- wrapping + clipping/trimming;
- unchanged font size.

### H5 — layout/shortcut semantics are global

The user’s reason for Fixed columns is spatial shortcut memory across Sets.

Round 3 already stores this globally in `PlacerSettings.Presentation`, but the Settings UI can read as though it belongs to the selected Set.

Product consequence:

- keep the global model;
- move the presentation UI to a clearly global area;
- no Set-specific column/shortcut state.

### H6 — Settings needs session Undo, not Save

The user does not value a separate “変更を保存” step.

The desired action is:

> 今回設定したけどやっぱりやめました。元に戻してください。

Product consequence:

- valid edits auto-commit through the existing protected store;
- keep an immutable session-open baseline;
- expose `今回の変更を戻す`.

### H7 — nested Settings wheel routing is broken

In “テンプレートをまとめて追加”, inner/outer scroll ownership prevents ordinary wheel navigation of the outer Settings surface in cases where scrollbar dragging still works.

Product consequence:

- add one edge-aware nested-wheel route.

### H8 — expression preset source is desirable

The user wants one-button switching between:

- existing Template expression source;
- tachie expression presets.

The user explicitly accepts an **experimental** compatibility model: try it, verify Preview, and stop using it in an environment where it does not work.

## 3. Private hands-on project structural observation

A user-supplied test project placed expression items side-by-side.

No private file/path/content is copied into this repository.

The derived structural observation was:

- one tachie implementation retained a selected preset by a face-side `Preset` string;
- YMM4 built-in PSD tachie stored the resolved face state (`FilePath`, enabled layers/paths) rather than the preset name.

Product consequence:

- do not require one universal preset serialization schema;
- treat “preset choice -> prepared FaceParameter” as the useful abstraction.

## 6. Evidence boundary

The Lab proves common capability patterns on the pinned host and synthetic third-party shapes.

It does **not** prove every third-party tachie plugin.

Round 4 therefore labels the feature experimental and must fail locally/reversibly.

No native evidence authorizes:

- arbitrary assembly-wide reflection;
- private-field writes;
- UI Automation;
- fake input;
- guessing a missing/ambiguous preset;
- deleting manual/unassociated expressions.
