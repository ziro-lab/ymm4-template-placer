# v0.4.2 Roadmap — Relative Intent Palettes

This roadmap starts from the native-verified v0.4.1 Candidate. It is a revision path, not permission to reimplement the proven placement core.

Primary design: `docs/V0.4.2_RELATIVE_PALETTE_DESIGN.md`.

## Baseline to preserve

Before every promotion checkpoint, retain:

- strict live YMM4 Template reference resolution,
- add-only normal placement,
- full-span collision checking,
- whole-operation preflight before Timeline mutation,
- unrelated/manual Item preservation,
- one YMM4 native Undo unit per user action,
- explicit failure instead of fuzzy source/target recovery,
- current package/install-folder verification,
- v0.4.1 regression ladder.

Do not merge `main` during this roadmap without explicit hands-on user acceptance.

---

## R1 — Freeze v0.4.2 semantics in tests/docs

Add proof fixtures for the concepts that currently fail or are undefined:

- logical CharacterName vs host Character object identity,
- Template with multiple Items,
- selected Item runtime type identification,
- 上 = smaller Layer, 下 = larger Layer,
- occupied first relative Layer must search farther in the same direction,
- one Template bundle preserves relative geometry.

No product behavior change required yet.

Exit:

- tests can represent these fixtures,
- old behavior is explicitly captured where migration will change it,
- no ambiguity remains about Layer direction vocabulary.

---

## R2 — Bundle-capable Template resolver

Refactor strict Template resolution so the exact live YMM4 Template is resolved independently of its Item count.

Required split:

```text
ResolveTemplate(entry) -> exact live ItemTemplate or Missing/Ambiguous
ResolveBundle(entry)   -> exact Template + 1..N source Items
CloneBundle(entry)     -> independent clones preserving relative geometry
```

Keep legacy single-item convenience functions temporarily for old code paths.

Do not yet change normal UI.

Exit:

- 1-item regression remains green,
- multi-item exact Template resolves successfully,
- missing/ambiguous refs remain unresolved,
- bundle clone contains no source object references,
- no Template body is copied into settings.

---

## R3 — Relative bundle Layer planner

Add a planner that can translate an entire bundle as one unit.

Required behavior:

- preserve relative source Layer offsets,
- preserve relative source Frame offsets,
- choose one common Layer translation,
- 上 searches only toward smaller Layer numbers,
- 下 searches only toward larger Layer numbers,
- every bundle member is checked over its own full duration,
- planned bundle members reserve occupancy against each other,
- fail atomically at configured search boundary.

Do not move existing Timeline Items.

Exit:

- blocked first candidate successfully escapes in the configured direction,
- opposite-direction wraparound never occurs,
- no partial bundle commit,
- one bundle placement = one native Undo.

---

## R4 — IntentPalette settings model

Introduce the new settings schema alongside conservative v0.4.1 migration handling.

Conceptual data:

```text
IntentPalette
  Id
  Name
  TargetContext
  Relation
  Ordered LibraryEntryIds
```

`TargetContext` includes Item type key, selection cardinality and optional CharacterName condition.

`Relation` includes finite time anchor / neighbor / fallback / 上下 / collision-search primitives.

Do not expose generic condition trees or scripts.

Exit:

- settings roundtrip is deterministic,
- missing Item type remains visible in Settings but inactive in normal editing,
- invalid/future schema is rejected without overwriting original settings,
- v0.4.1 settings are preserved until successful migration save.

---

## R5 — Character bootstrap and unified CharacterName semantics

Implement first-setup scan of live YMM4 Templates.

For every eligible CharacterName:

- create the first expression Palette automatically,
- name it with the CharacterName,
- import all eligible expression Templates,
- include eligible multi-item Templates,
- deterministic initial ordering,
- do not continuously re-import after setup.

Rules:

- Palette/expression applicability uses logical CharacterName,
- Template source identity remains strict TemplateLocator,
- a Template containing multiple different CharacterNames is not auto-assigned,
- same Character may own multiple Palettes (`Name`, `Name 2`, ...).

Exit:

- the current “Palette entry exists but Voice expression candidate does not” mismatch is eliminated for same logical CharacterName,
- deleting/reordering bootstrap entries remains user-owned,
- explicit rescan does not silently undo user organization.

---

## R6 — SelectionContext and Palette filtering

Create one context snapshot from public Timeline selection.

Required:

```text
selected Item runtime type
selection count
CharacterName when available
selected span/layer geometry
```

Normal UI filters IntentPalettes from this context.

Exit:

- Voice selection shows only Voice-compatible Palettes,
- another Item type replaces them immediately,
- Character-specific Palette appears only for matching logical CharacterName,
- irrelevant Palettes are hidden, not disabled,
- no polling/private Timeline ViewModel reflection is introduced.

---

## R7 — Normal action surface: tabs + tiles

Replace the high-frequency dropdown/list interaction with the intended action surface.

Required:

- applicable Palette intents shown as tabs/segments,
- entries shown as wrapping action tiles/buttons,
- horizontal space is used before vertical scrolling,
- single-click action path is native-tested,
- last valid Palette can remain active per context where safe,
- edit/reorder/delete controls move to Settings.

Empty state:

```text
この種類のアイテム用のパレットはまだありません
[設定を開く]
```

Exit:

- target selection + optional tab switch + one tile click is the normal placement path,
- no layer/profile/template-management decisions appear in that path.

---

## R8 — Finite RelationResolver

Implement Palette-owned relative relation planning.

Initial primitives:

- selected start/end/center,
- selected range start/end,
- pair boundary,
- previous/next same Item type,
- previous/next same CharacterName,
- previous/next same type + same CharacterName,
- Template intrinsic duration,
- match target span,
- fixed duration,
- explicit start/end offsets,
- explicit missing-neighbor fallback,
- 上 / 下 / limited relative offset,
- same-direction collision escape.

Do not add arbitrary property conditions or boolean expression trees.

Exit:

- Voice -> next same Character expression relation works without a special duplicated Character rule,
- Video-end style relation can be expressed using the same engine,
- missing neighbor follows configured fallback or fails explicitly,
- RelationResolver itself performs no Timeline mutation.

---

## R9 — Palette execution over PlacementPlan

Wire:

```text
SelectionContext
-> IntentPalette
-> Palette entry
-> strict bundle resolution
-> RelationResolver
-> bundle translation/collision search
-> PlacementPlan
-> native Undo commit
```

Existing v0.4 Profile implementations may be reused internally where they exactly match a relation primitive, but they are no longer the primary normal-work UI taxonomy.

Exit:

- concrete tile executes the Palette's saved relation,
- no repeated layer/profile configuration is required,
- source bundle geometry and unrelated Timeline Items remain unchanged,
- stale selection invalidates the plan before mutation.

---

## R10 — Expression list consumes Character Palettes

Refactor bulk Voice expression candidate generation to use the same IntentPalette data.

Required:

- Voice row CharacterName -> applicable expression Palettes,
- candidate union follows Palette order then entry order,
- membership changes appear after refresh,
- reordering changes candidate priority,
- identical aliases receive collision-only Palette/source context,
- hidden host object identity does not suppress same-name candidates.

Keep Excel as the secondary bulk assignment bridge.

Exit:

- there is one Character expression source of truth,
- normal action surface and bulk Voice list agree about candidate availability.

---

## R11 — Settings workspace

Move low-frequency organization into Settings.

Required editors:

- Palette target Item type,
- optional Character filter,
- intent name,
- relation summary/editor,
- neighbor/fallback choice,
- 上/下 and search bounds,
- membership tiles/list,
- reorder/delete,
- duplicate Palette,
- add from live Templates,
- explicit Template rescan/import,
- unavailable target type/broken source diagnostics.

Settings should phrase relations in editing language, not raw engine terms.

Exit:

- normal editing surface contains no Palette construction controls,
- initial Character bootstrap can be cleaned/reordered quickly,
- changing a setting immediately explains what future clicks will do.

---

## R12 — Selection Placement migration

Remove the mismatch where Selection Placement chooses from the full Library independently of Palette intent.

Required:

- selected context chooses applicable IntentPalettes,
- normal concrete choices come only from the active Palette,
- repeated Profile/Preset dropdown decisions disappear from the common path,
- Target Companion / Point / Range / Boundary remain available internally or through configured Palette relations as appropriate.

Do not delete legacy behavior until native parity is proven.

Exit:

- no ordinary selection-placement path displays unrelated Library entries,
- each configured intent can be executed from the same tabs/tiles model.

---

## R13 — Multi-item expression association / Resync decision gate

Only after general bundle placement is native-proven, evaluate associated multi-item expression bundles.

Must prove before enabling:

- one Voice may own several generated bundle members,
- every generated member has unambiguous association identity,
- selected source/member Resync has deterministic scope,
- geometry update is all-or-nothing for the bundle,
- one native Undo restores the whole update,
- no fuzzy reconstruction after member deletion/copy.

If this requires a second persistent graph or connected-clip engine, keep it out and allow bundle Quick/relative placement without bundle Resync.

---

## R14 — Final native acceptance and Candidate package

Run the full original regression plus v0.4.2 acceptance.

Minimum evidence:

- old v0.4.1 placement/Undo/reference safety gates remain green,
- first setup Character bootstrap,
- Item type filtering,
- CharacterName filtering,
- multiple same-Character Palettes,
- tabs + wrapping action tiles,
- upper/lower collision escape semantics,
- multi-item bundle geometry/collision atomicity,
- normal click execution,
- expression list consistency,
- Settings isolation,
- exact release DLL native smoke,
- fixed `Ymm4TemplatePlacer/` package root,
- zero warnings/errors.

Keep the integrated PR Draft until the user installs and validates the Candidate in their own editing workflow.
