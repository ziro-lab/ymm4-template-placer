# v0.4.2 UI/UX Mental Model Addendum

This document is authoritative for the v0.4.2 user-facing surface. It supplements `V0.4.2_RELATIVE_PALETTE_DESIGN.md`; it does not replace the proven placement, resolver, bundle, reference or Undo cores.

## Success model

The normal editing path is:

```text
select the Item
→ see what can be done to this Item
→ switch Set only when needed
→ click the concrete action
```

The user should think about the edit they want, not whether the operation belongs to Palette, Selection Placement, Profile or Preset internals. A decision already saved in a Set must not be asked again during ordinary editing.

## Normal surface

The primary relative surface is task-oriented. Selection is the first filter and removes irrelevant intents before rendering the screen.

```text
selected Item / Character / useful content
↓
[expression] [reaction] [subtitle] ...
↓
Set, only when one intent has multiple alternatives
↓
[action tile] [action tile] ...
```

Intent is the top switching level. Multiple Palettes that share one intent are Sets below it. Concrete entries are executable tiles, not selections that open another placement decision.

The compatibility Palette / Selection Placement taxonomy may remain only in the explicit legacy workspace. The secondary bulk Voice workflow may remain separate, but its label and wording should describe the user task rather than an engine subsystem.

## Set switching

A small high-frequency Set collection should use always-visible segments/small tabs. This saves a click and makes current state visible. Large Set collections may fall back to a picker to avoid crowding the editing surface.

## Progressive Settings

Settings is a low-frequency setup surface. It must reveal only parameters required by the current choices.

Examples:

- TargetSpan hides fixed duration.
- A relation that does not use a neighbor hides neighbor edge, maximum gap and missing-neighbor fallback.
- Pair-boundary tolerance appears only for a pair-boundary anchor.
- Character details appear only when Character restriction is enabled.
- Multi-type matching semantics appear only after multiple Item types are selected.
- Start/end offsets, layer bounds and similar uncommon tuning live under Advanced.

Hidden irrelevant text must not block Save merely because a formerly visible field contains invalid draft text.

## User decisions, not engine parameters

Settings should group one user decision as one control even when the engine stores several fields.

Choosing `上` or `下` also defines same-direction collision escape. Normal Settings does not ask the user for a second collision-direction decision. Bundle internal relative geometry is preserved without asking. Face/Voice context should receive useful defaults rather than making the user rebuild the common relationship from individual primitives.

Raw GUIDs, runtime type keys and other internal identifiers stay out of the ordinary surface.

## Relation summary

The selected Set must show a natural-language summary of the result, for example:

```text
小夜のボイスを選んだとき、選択アイテムの開始から
次の同じ種類・同じキャラのアイテムの開始まで、
対象より上の空いているレイヤーへ配置します。
塞がっていればさらに上へ探します。
```

The summary is a verification aid: a user should be able to understand the saved behavior without mentally decoding the parameter form.

## Normal state vs problem state

Do not decorate normal usable actions with repeated `Ready`, `使用可能` or explanatory prose. Usable actions are simply visible and actionable. Unavailable irrelevant actions should be hidden where practical.

When an operation cannot run, show a short reason and next action. Empty states must lead somewhere useful, such as `新しく設定する` or `演出を追加する`; they must never fall back to an unrelated full Library.

## Beginner and expert target

A beginner should discover the main path by selecting an Item and looking at the screen. An expert should be able to repeat that path with selection + at most an intent/Set switch + one tile click, without repeated parameter confirmation.

## Native UI/UX acceptance

Feature existence is not enough. Native proof must cover all of the following:

1. Item selection exposes only meaningful intents for the current context.
2. Normal top-level wording is task-oriented and does not require Palette / Selection Placement taxonomy.
3. Intent and Set are distinct levels; small Set collections use visible segments and large collections have a deliberate fallback.
4. A tile performs the saved placement directly; Profile, Preset, Layer number, Relation and Template management are not repeated normal-path decisions.
5. Progressive disclosure changes actual WPF visibility as relation choices change.
6. Settings provides a natural-language relation summary; Advanced is collapsed by default.
7. Empty states are actionable and never expose the unrelated full Library.
8. Narrow width keeps selection context, intent, Set, tiles, Settings discovery and Save understandable.
9. Raw type keys/internal IDs are absent from ordinary user-facing controls.
10. These UI changes preserve zero-write navigation, PlacementPlan/preflight, native Undo and every retained regression gate.

The dedicated native marker is `RELATIVE_UIUX=PASS`. The run also emits `v042-uiux-acceptance.json`; packaging must reject a build without current UI/UX evidence.
