# v0.4.2 Hands-on UX polish — acceptance matrix

This matrix is additive to the existing v0.4/v0.4.1/v0.4.2 regression ladder. It must not be used to delete or weaken historical acceptance.

## A. Placement surface

- A1 `編集` is replaced by `配置` in the new normal workspace; compatibility labels remain isolated.
- A2 tile label priority is explicit alias -> last semantic Template path segment -> original Template name.
- A3 duplicate short labels remain distinguishable without exposing IDs/CLR names.
- A4 live YMM4 Template names/locators are byte/identity unchanged by alias edits.
- A5 tiles use a uniform near-square layout and remain readable/reachable at 360px.
- A6 drag reorder changes only entry order; no placement command fires during drag.
- A7 reordered entries persist/reload and expression candidate priority follows the saved order where that contract already applies.
- A8 finite tile color metadata persists/reloads; neutral is the default; text remains legible.
- A9 single click still executes the saved placement with one complete preflight and native Undo semantics.

## B. Item-first Settings

- B1 selected Timeline Item appears as the primary Settings context.
- B2 only intents/Sets relevant to that context are offered before engine details.
- B3 ordinary Voice setup does not begin with the complete runtime type checkbox matrix.
- B4 multi-type targeting is available only as an explicit advanced/special configuration.
- B5 built-in Item names are user-facing Japanese; `TransitionItem`, `FrameBufferItem`, namespace-qualified keys and GUIDs do not appear in normal Settings.
- B6 existing progressive disclosure rules still operate on actual WPF visibility.
- B7 natural-language relation summary updates with the current draft.
- B8 hidden irrelevant invalid text does not block Save.
- B9 draft/save/discard/external-modification protection remains intact.
- B10 Settings navigation/editing is Timeline zero-write.
- B11 optional bulk Set management, if added, is contained inside Settings and does not become a fourth main task.

## C. Expression specialist workflow

- C1 double-clicking a Voice row moves CurrentFrame to the Voice start by a proved host route.
- C2 navigation itself does not add/delete/move Timeline items or write settings.
- C3 selecting an expression immediately applies one associated whole bundle.
- C4 changing the selection for the same Voice produces exactly one final associated bundle, not old+new stacking.
- C5 replacement strict-resolves the new Template and completes all relation/collision/Character/source validation before removing/replacing the old result.
- C6 a failed replacement leaves the old associated bundle untouched and returns the selector to the actual state.
- C7 `— 配置しない —` removes only that Voice's exact Plugin-managed associated bundle.
- C8 manual/unassociated Faces and unrelated Plugin items are never removed or rewritten.
- C9 multi-item expression Templates replace as one whole bundle while preserving internal Frame/Layer/Length/content geometry.
- C10 canonical Character rebind and saved Face/effect state use the proven Template-fidelity path.
- C11 reopening/refreshing the list derives the current row selection from exact association identity, never proximity/text/order guessing.
- C12 one Voice's rapid candidate trial satisfies the proved native Undo/coalescing policy. If the pinned host exposes no safe route, this item must be reported BLOCKED rather than faked.

## D. Host integration

- D1 the exact `IToolPlugin` surface is recorded for the pinned host.
- D2 `ツール > ユーティリティ` placement is implemented only if supported by a proved host/plugin API; otherwise the current Tool location remains and the item is BLOCKED with evidence.
- D3 Item display names use a proved host localization provider when available; otherwise a bounded built-in resolver never exposes fully-qualified CLR names in normal UI.

## E. Safety/regression

- E1 `TEMPLATE_FIDELITY=PASS` remains mandatory.
- E2 `RELATIVE_UIUX=PASS` remains mandatory.
- E3 add `HANDS_ON_UX_POLISH=PASS` plus a current JSON manifest.
- E4 independent evidence consumer rejects missing/stale/failed/duplicate new-stage evidence.
- E5 Release and Proof builds remain 0 warnings / 0 errors.
- E6 exact distribution DLL native smoke passes.
- E7 `.ymme` root remains `Ymm4TemplatePlacer/` and archived DLL hash matches the native-smoked distribution DLL.
- E8 `main`, PR #6 and accepted baseline remain untouched until hands-on acceptance.

## Human acceptance still separate

Native PASS does not claim real-user PSD rendering fidelity. After the automated pass, hands-on acceptance should still sample actual 小夜/ミコ Templates, PsdTachie layer paths, representative CharactorMotion values, drag ergonomics, Settings comprehension and the high-throughput expression workflow.
