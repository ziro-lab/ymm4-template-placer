# v0.4.2 Hands-on Round 3 — frozen design

## Purpose

This round turns the real-user Hands-on Round 2 feedback into a smaller, faster editing surface without rewriting the proven placement core.

The product direction is:

> **a stable context palette that can be learned spatially and operated quickly by mouse or position shortcut**

Round 3 is additive over PR #14 source `a553ae8c32eeb8c1f125b8c005095bbe6fc98ebb`.

Do not redesign:

- `IntentExecutionPlan`
- `QuickDropPlanner` as the Generic backend
- `PlacementPlan`
- Template resolution / bundle fidelity
- association identity
- native Undo/Redo
- staged Settings protection
- expression replacement/removal safety

## 1. Placement tile surface

### Remove the obsolete drag accent

Whole-tile drag is already proven. Remove the small horizontal "grab" bar.

The existing finite color value must visibly affect the tile itself, not only a tiny accent.

Use the existing finite color enum. Render it as a readable tile-face treatment such as:

- subtle tinted face/background;
- clear border/accent;
- system text foreground remains authoritative;
- High Contrast falls back to system brushes.

Do not add arbitrary RGB/color-picker storage in this round.

### Set-wide shape action

The selected Set exposes a secondary **Set-wide settings** action from the placement surface.

At minimum:

- 角丸
- 四角
- 丸

"Set-wide shape" is a bulk write over the current entries. Do **not** invent inherited Set-default shape semantics.

After bulk apply, one tile may still be changed individually.

The same Set-wide command should be reachable from the Set affordance and may also be linked from a tile context menu as "このSet全体の設定".

## 2. Stable grid and position shortcuts

### Layout

Preserve the current responsive layout as **Auto**.

Add **Fixed columns** as an explicit layout mode.

Global presentation settings are preferred over per-template metadata:

```text
LayoutMode = Auto | Fixed
FixedColumns = bounded positive integer
```

Fixed mode must never silently change the column count because the Tool is resized. If space is insufficient, keep spatial ordering stable and use clipping/scrolling or smaller available width without reflowing to a different column count.

### Shortcut identity is position, not tile

A shortcut is assigned to a visible slot index, not to a Template/LibraryEntry/IntentEntry ID.

Example with 4 fixed columns:

```text
slot 0 = row 1 / column 1
slot 1 = row 1 / column 2
slot 4 = row 2 / column 1
```

Reordering tiles changes which tile occupies the shortcut slot. No shortcut metadata travels with the tile.

Position shortcuts are global to the placement palette so the same physical key layout means the same spatial position across Sets/contexts.

No shortcut is enabled by default. User-configured bindings must be explicit to avoid stealing YMM4 shortcuts.

### Shortcut admission

Shortcuts may operate while keyboard focus is elsewhere in the YMM4 main window, but only when:

- Template Placer is visible;
- the normal placement surface is active;
- layout is Fixed;
- the configured slot exists in the currently selected Set;
- the tile is available;
- no modal dialog/context menu is active;
- the keyboard source is not a text/editor/ComboBox/DataGrid-edit input;
- the event is not an auto-repeat.

Only an admitted configured shortcut is handled. Unknown/unavailable input must remain available to YMM4.

Use the existing bounded application-input lifecycle pattern. Do not register OS-global hotkeys.

## 3. Settings simplification

### Item types

Remove the common-path "その他" bucket.

Render all currently available target Item types directly in the target selector, with stable ordering and Japanese display names where known.

The normal list may wrap to approximately two rows. Do not add another hierarchy merely to save one row.

Mixed/multi-type targeting remains Advanced.

### Compatibility workspace

Remove normal user-facing entry points for:

- 以前の設定・互換操作
- legacy Quick Drop / selection workspace switching
- "相対パレットへ戻る"

Preserve serialized legacy data and compatibility code. This is a UI removal, not a destructive migration.

A previously saved `LegacyWorkspace=true` must not strand the user in a hidden workspace: Round 3 normal startup always enters the current common workspace.

A future maintenance-only recovery entry may be added only if a concrete recovery need appears.

## 4. Generic layer targeting

Public Lab evidence did **not** establish a semantic clicked-layer route. Do not derive a layer from screen Y / row height.

Round 3 therefore ships **numeric target layer only**.

The Generic placement surface exposes the target layer directly for fast operation.

The saved Generic Set keeps the existing layer bounds. The quick target is the Set's preferred/target layer and must stay inside those bounds.

When the target layer is occupied, expose exactly these finite behaviors:

- 配置しない
- 上の空きを探す
- 下の空きを探す

Host/product convention remains:

- 上 = smaller layer number
- 下 = larger layer number

Search is one direction only, bounded by saved layer limits, with no wrap to the opposite side.

Never move/shorten existing Items.

Implement this as a small additive search-policy parameter over the existing `LayerPlanner`; do not create a Generic placement engine.

Legacy LayerPolicy behavior for older settings must remain intact. New one-direction behavior needs an additive default so old JSON preserves old meaning.

## 5. Expression list freshness

Remove the top-level **シーン更新** button from normal UI.

Keep refresh capability internally/secondarily for recovery/testing, but normal expression rows should stay fresh automatically.

Use a bounded Voice snapshot identity/signature over:

- Voice object/reference identity within the current Timeline;
- CharacterName;
- Frame;
- Length;
- Layer;
- Serif.

Do **not** include association Remark tags, so Plugin-managed expression writes do not cause a pointless row rebuild.

Freshness checks are event-driven:

- scene/Timeline replacement;
- Timeline Item collection changes;
- current Voice Item property changes;
- entering the expression tab.

Coalesce repeated notifications and rebuild only when the Voice signature actually changed. No polling timer.

If an Excel/import batch is pending, do not silently discard it. Mark it stale and require explicit recovery/re-import/secondary refresh rather than rebuilding over pending work.

The empty state should say that adding Voice Items is detected automatically; it must not instruct the user to press シーン更新.

## 6. Expression row navigation: Timeline + Preview/playback + viewport

Hands-on and Public Lab established that `Timeline.CurrentFrame` alone can move the visible playhead while actual Preview/playback seek state remains stale.

Normal row navigation becomes:

```text
targetFrame = Voice.Frame
close expression trial session
Timeline.CurrentFrame = targetFrame
Timeline.SelectItem(Voice)
await supported Preview seek(targetFrame)
apply viewport-follow policy
```

### Preview seek capability

Observed exact-host public surface:

- `PreviewViewModel.SeekAsync(int)`
- `TogglePlayAsync()`
- `StopAsync()`

Use a **bounded capability adapter**, not a YMM4 version-number gate.

Preferred implementation:

1. locate the known live Preview View/DataContext inside the YMM4 main window;
2. require the exact expected PreviewViewModel type/surface;
3. use the public `SeekAsync(int)` path;
4. if the capability is absent/changed, keep CurrentFrame/Selection navigation working and report that Preview/playback synchronization is unavailable.

Do not use:

- fake Timeline clicks;
- UI Automation;
- arbitrary assembly scans;
- private playback fields;
- CurrentFrame jiggle/walk-back hacks;
- `FocusService.Focus()` as Preview synchronization.

Lab proved `TimelineViewModel.FocusService.Focus()` targets the Timeline serif-input focus path, not Preview refresh.

### Latest-wins async navigation

Seek is asynchronous and row clicks may be rapid.

The root coordinator owns a small latest-wins navigation state:

- every admitted click may update visible CurrentFrame/Selection immediately;
- at most one seek worker is active;
- while a seek is active, keep only the newest pending row/frame;
- after the current seek completes, seek the newest pending target;
- stale completions must not overwrite status/viewport decisions for a newer row.

Do not put async orchestration in sibling Views.

### Timeline viewport follow

Observed exact-host public surface:

- `TimelineViewModel.ContainFrameInViewport(int)`
- `TimelineViewModel.ScrollFrame(int)`

Expose:

- 追従しない
- **画面外の時だけ追従** (default)
- 常に追従

Behavior:

```text
Off:
    do nothing

WhenOutside:
    if !ContainFrameInViewport(frame)
        ScrollFrame(frame)

Always:
    ScrollFrame(frame)
```

`ScrollFrame` must not be used as a Preview-refresh substitute. Its job here is viewport movement only.

If the viewport capability is unavailable on a future host, row navigation and Preview seek (if available) continue independently.

## 7. Presentation metadata size

Round 3 may add a small optional presentation/settings envelope for:

- Auto vs Fixed column mode;
- fixed column count;
- explicit position shortcut mappings;
- expression viewport-follow mode.

Do not attach shortcut bindings to individual tile identities.

Set-wide shape is a bulk operation over existing per-entry shape fields and needs no new inheritance model.

## 8. Compatibility principle

YMM4 version number alone never disables a feature.

Each host-sensitive feature is independently capability-gated:

- context pointer classification;
- Preview seek;
- viewport contain/scroll.

If one capability changes, only that feature degrades and reports a concise compatibility notice.

## 9. Non-goals

Round 3 does not add:

- clicked-layer coordinate inference;
- arbitrary shortcut scripting/macros;
- per-template shortcut ownership;
- arbitrary color picker;
- generic rule/DSL engine;
- automatic Preview fake input;
- continuous scene-wide association synchronization;
- destructive migration of legacy settings;
- placement-core rewrite.
