# YMM4 Template Placer v0.4.2

対象: **YukkuriMovieMaker4 4.55.1.1 Lite**。このCandidateは実機受入れ前の版です。最初は普段のプロジェクトを別名保存したコピーで試してください。

## 最初に

YMM4のテンプレート機能へ、再利用したいアイテムを登録します。複数アイテム入りのテンプレートも使えます。元テンプレート本体をプラグイン設定にコピーすることはありません。

主画面は「編集」「表情をまとめて」「設定」です。普段は「編集」で基準アイテムを選ぶと、そのアイテムに対してできることだけが表示されます。内部のPalette / Selection Placement分類を選ぶ必要はありません。

初回は表情アイテムを含むテンプレートを走査し、キャラクター名ごとに表情セットを作ります。複数キャラクターが混在するテンプレートや元を一意に特定できないものは自動登録しません。

初回取り込みはメモリー上で行い、ロードだけで既存設定ファイルを変更しません。セット名・並び順などを編集し「変更を保存」すると確定します。保存前に閉じた場合は次回に同じ条件で取り込み直します。

## 普段の配置

タイムラインで基準にするアイテムを選び、「編集」に表示された「やりたいこと」を選びます。同じ用途のセットが少数なら常時見えるボタンで切り替え、多い場合だけ一覧から選びます。最後に具体的な演出タイルを1クリックします。

選択アイテムの種類・選択数・キャラクター条件が合う用途だけ表示します。何も選んでいない場合は配置できません。同種の複数選択や異種の組み合わせは、その条件を明示的に設定したセットだけが対象です。

用途やセットの切替だけでタイムラインや保存済み設定は変わりません。タイル実行時に最新状態で配置を計画します。通常画面ではレイヤー番号や配置プリセットを毎回選びません。

同じタイルを再度押すと別の追加操作になります。タイル配置は音声との再同期用関連付けを作りません。関連付けが必要な場合は「表情をまとめて」から配置します。

## セットを作る・整理する

基準にしたいアイテムを選んでから「設定」の「＋ セット」を押すと、その種類・選択数・キャラクター名を初期条件に使います。対象を選ばずに作成することはできません。ボイス＋キャラクターを選んだ場合は、表情でよく使う「選択ボイス開始→次の同種類・同キャラ開始、なければ現在ボイス終了」を初期値にします。

「やりたいこと」の名前が同じセットは、通常画面では同じ用途タブにまとまります。セット名は自由に付けられ、同じキャラクター向けのセットを複数作れます。

設定では、まず現在のセットが何をするかを自然文で確認できます。選んだ配置方法に必要な項目だけを表示し、固定長・周囲参照・境界許容差・キャラクター条件などの不要な欄は隠します。開始/終了差分や探索レイヤー範囲など頻度の低い調整は「詳細設定」にまとめています。「演出と並び順」の上下ボタンで順番を変更し、不要な候補を外せます。セット自体の複製・並べ替え・削除もできます。

変更は保存するまで下書きです。「変更を保存」で検証して確定し、「変更を破棄」で保存済みへ戻します。保存に失敗した場合は入力を残し、外部変更を勝手に上書きしません。下書き編集中でも通常画面の配置は保存済みのルールを使います。

新しい設定画面の未保存下書きは、Toolを閉じる前に保存してください。旧操作向けの途中作業復元が、新しい設定下書きにも全て適用されるとは限りません。

## テンプレートをまとめて追加する

追加先セットを選び、「テンプレートをまとめて追加」で必要なものにチェックを付け、「チェックしたテンプレートを追加」を押します。1件でも複数件でも同じ操作です。検索で隠れたチェック済み項目も選択を保持します。

まず全件を検証してから下書きへ追加します。元がなくなった、参照が曖昧、キャラクター条件が違うなどの問題が1件でもあれば一括追加全体を止めます。「変更を保存」までは保存済み設定を変えません。

YMM4側へ後から表情テンプレートを増やしても自動追加し続けません。「新しい表情を取り込む」で未取り込みの元だけ追加します。一度取り込んでセットから外した候補は、この操作で勝手に復活させません。必要なら手動で選び直して追加してください。

## 配置関係とレイヤー

基準は選択アイテムの開始・終了・中央、選択範囲の開始・終了、2件の境界などです。周囲参照には前後の同種類・同キャラ・同種類かつ同キャラを指定できます。

例えば単体の表情なら、「選択ボイスの開始」から「次の同種類・同キャラ」まで、見つからなければ「現在の対象の終了まで」という設定が使えます。動画の終了に短い演出を置くなら、基準を終了・長さを固定にします。

最大間隔や参照先がない場合の動作も保存します。「配置しない」は何も追加しない正常な結果です。曖昧な周囲アイテムを推測して使うことはありません。

**上は小さいレイヤー番号、下は大きいレイヤー番号**です。最初の候補が塞がっている場合は設定範囲内を同じ方向だけ探索します。反対側へ回り込まず、既存アイテムを動かして場所を空けません。衝突は配置予定の時間全体で検査します。

開始・終了差分や固定長はフレーム単位です。無効な数値、負の開始、長さ0、範囲外の計画は配置前に止めます。

## 複数アイテム入りテンプレート

内部の最小開始フレームを0として、各アイテムの時間差・レイヤー差・長さ・内容を維持します。衝突時も全メンバーを同じレイヤー差で移動し、全件を置けなければ1件も置きません。配置全体をUndo1回で戻せます。

自動取り込み・一括追加では複数アイテム用に「テンプレート内の長さを維持」を設定します。内部の長さを変える指定と両立しない場合は、勝手に伸縮せず停止します。Bundleは配置の単位であり、YMM4のGroupを新しく作る機能ではありません。

## 表情をまとめて・Excel

「表情をまとめて」はシーンのボイスごとに候補を選び、「表情を配置」でまとめて配置します。「このセットの表情を、「表情をまとめて」の候補にも使う」を有効にしたパレットが候補元です。

キャラクター名で絞り、セット順・演出順に候補を集めます。同じ元が複数セットにある場合は先に出た登録を使います。違う配置方法で同じ元を使い分けたい場合は、通常パレットでセットを選んで実行してください。同名候補には必要な場合だけセット名・元名を補います。

候補なしの行は「＋ 表情を追加」から設定へ進めます。保存後も勝手に表情を割り当てません。未選択行には配置しません。

「Excelでまとめて編集」では、出力したAssignmentsシートのテンプレート列だけを編集します。読み込みは割り当てを更新するだけで、タイムラインは変えません。配置時はその時点の保存済みパレット設定を使います。音声・元テンプレートが変わった場合は再出力してください。

## 関連付けと手動再同期

「表情をまとめて」から配置したアイテムには、元ボイスとの弱い目印を付けます。複数アイテム入りの場合は全メンバーを識別します。元テンプレートやユーザーの備考本文は保持します。

関連ボイス、またはBundleのいずれかのメンバーを選んで「選択した表情を再同期」すると、そのBundle全体へ現在保存されている配置関係を再適用します。音声移動だけでは自動追従しません。

メンバーが削除・コピーされた、元の構成が変わった、対象が重複して特定できない場合は、そのBundle全体をスキップします。部分再構築はしません。複数Bundle中の一部だけ成功する場合はスキップ理由を報告し、成功した更新群をUndo1回で戻せます。

## 旧設定・参照切れ

旧Library・キャラクター/Style Palette・表情/選択Presetは保持します。絶対配置など意味を一意に変換できない設定を新しい相対ルールへ勝手に移しません。

設定の「以前の設定・互換操作」から旧Quick Drop、旧選択配置、テンプレート管理を使えます。元の改名・移動で参照切れになった場合の再リンクはテンプレート管理で明示的に行います。「相対パレットへ戻る」で通常画面へ戻ります。旧操作の詳細はソースZIP内の`docs/USAGE_V0.4.1.md`にあります。

同名の実キャラクター定義がホストに複数登録されている場合は、候補の論理分類とは別に、配置時の安全確認で停止します。一意にしてから操作してください。

## インストールと検証範囲

`.ymme`内部は固定の`Ymm4TemplatePlacer/`です。過去のCandidateで`Ymm4TemplatePlacer-v0.x.y`というフォルダが複数残っている場合は、YMM4を閉じて設定・プロジェクトをバックアップし、該当する旧Template Placerの版付きフォルダだけを整理してください。他プラグインや素材は削除しないでください。

Native検証の基準ホストはYMM4 4.55.1.1 Liteです。ただしYMM4のバージョン番号だけを理由に機能停止はしません。新しいYMM4でも既知のpublic/WPF依存関係が維持されている機能はそのまま動作します。タイムライン連動に必要な依存型が実際に変更・削除された場合は、その自動Set切替だけを使えない旨を画面に表示し、配置・設定・表情など他の機能は継続します。実PSD素材の全描画、他プラグインとの全組み合わせ、物理マウス・インストーラ操作、全DPI/theme、未検証YMM4での完全互換、クラッシュ後の下書き復元は未保証です。

配置は追加専用です。自動削除・自動置換、曖昧な参照の修復、汎用ルール言語、常時同期は行いません。実行した検証・ホスト・DLLのハッシュは配布物の`provenance.json`を確認してください。
