## L2 — Timeline viewport follow

Experiment: `timeline-navigation-handoff`

Observed public exact-host surface:

- `TimelineViewModel.ContainFrameInViewport(int) : bool`
- `TimelineViewModel.ScrollFrame(int) : void`
- `TimelineViewModel.Viewport`

Observed:

- near frame visible = true;
- far frame visible before navigation = false;
- direct `CurrentFrame + SelectItem` did not scroll the far frame into view;
- after `ScrollFrame(farFrame)`, far frame visible = true;
- `ScrollFrame` did not change `Timeline.CurrentFrame`.

Evidence:

- final source `4e8454a5c6520ca0d45a2f7c9f4da79cd174fd2a`
- run `35447556976`
- job `105909011952`
- artifact `10585526864`
- artifact SHA256 `d7bb0705212713e2e9d10dc9feda17b7aa599062919abfb1a77f99696505f822`

Product decision: support Off / WhenOutside / Always. Default WhenOutside.

## L3 — WPF focus / FocusService is not Preview synchronization

The same navigation experiment observed:

- a real Timeline Item click did not move keyboard focus into the TimelineView route;
- it did not raise `TimelineViewModel.FocusService.FocusRequested`;
- calling public `FocusService.Focus()` did raise the event, but keyboard focus landed in the `SerifInputRowViewModel` TextBox route.

Product decision: do not use ordinary WPF focus or `FocusService.Focus()` to refresh Preview.

CI pixel-level Preview fixture remained unusable, so pixel repaint by itself was not claimed from this experiment.

## L4 — displayed CurrentFrame vs actual playback seek

Experiment: `timeline-playback-start-sync`

Public Preview surface observed:

- `PreviewViewModel.SeekAsync(int)`
- `PreviewViewModel.SeekAsync(TimeSpan)`
- `PreviewViewModel.TogglePlayAsync()`
- `PreviewViewModel.StopAsync()`
- `IsPlaying`
- `CurrentPositionRate`
- `StartPosition`

Three real playback starts were compared.

### Timeline only

Displayed target:

```text
Timeline.CurrentFrame = 180
SelectItem(...)
```

Playback frames:

```text
0, 3, 5, 12, 15, 18, 20, 22, ...
```

Result: playback did **not** start near displayed frame 180.

### Timeline + public Preview seek

Then:

```text
await PreviewViewModel.SeekAsync(180)
```

Playback frames:

```text
182, 185, 187, 189, 191, 194, ...
```

Result: playback started near displayed frame 180.

### Native ruler control

Real ruler click displayed frame 546.

Playback frames:

```text
548, 550, 552, 555, 557, 560, ...
```

Result: native control also started near its displayed frame.

## Evidence boundary

These are exact-host observations, not timeless YMM4 contracts.

Round 3 production code must be capability-based and fail locally:

- missing clicked-layer route -> numeric layer remains;
- missing Preview seek -> CurrentFrame/Selection/viewport remain;
- missing viewport surface -> CurrentFrame/Selection/Preview seek remain.

Do not replace a missing capability with coordinate inference, fake input or private state.
